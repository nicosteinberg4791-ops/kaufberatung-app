# Prüfauftrag: App-Hülle der Kaufberatung (PWA), Erstprüfung

**Ziel:** Die Hülle macht die unveränderte Kaufberatung (eine HTML-Seite) zu einer installierbaren, offline nutzbaren Android-App auf GitHub Pages, ohne Server und ohne Geheimnisse.

**Fertigkriterien**
- Installierbar (Manifest, Symbole any+maskable), Service Worker aktiv, Offline-Neuladen zeigt die Seite.
- Update: neue Fassung wartet, Karte „Neu laden“ aktiviert sie und lädt die Seite genau einmal neu; erster Besuch ohne Doppel-Laden.
- `window.claude.use("db"|"user")`-Ersatz bedient genau die Aufrufe der Seitenskripte (siehe Prüffrage 2); fremde Daten (preise.json, localStorage) nur geprüft und als Text.
- Wunschpreise bleiben auf dem Gerät; Repo und Seite enthalten keine Zugangsdaten.
- `preise_aktualisieren.py` schreibt Tiefstpreis/Verlauf fort, behält bei fehlendem Angebot den alten Stand, pusht nur aus dem gh-pages-Arbeitsbaum.

**Betroffene Dateien:** app/app.js, app/sw.js, app/app.css, app/manifest.webmanifest, werkzeuge/app_bauen.py, werkzeuge/preise_aktualisieren.py, werkzeuge/veroeffentlichen.py, tests/test_app.py. Referenz nur lesen: werkzeuge/preiswecker.py (`abgleich`).

**Selbstprüfung:** `powershell -File tests/alle-tests.ps1` → Fehler 0 (15 Tests). Chrome headless über DevTools-Protokoll (`werkzeuge/browserpruefung/pruefe.mjs`, `update.mjs`): 375 px hell/dunkel Querscrollen 0, Konsole leer, `getInstallabilityErrors` leer, SW aktiv, Offline-Neuladen mit 5 Preisen aus Cache, Treffer-Karte, Update-Ablauf; mit Runde-6-Inhalt zusätzlich Wunschpreis setzen/löschen, Touch-Ziele ≥ 44 px.

**Bekannte Grenzen:** Hintergrund-Benachrichtigung nur als Versuch (Periodic Background Sync, Zeitpunkt vom Browser). `veroeffentlichen.py` noch nicht gegen ein echtes Remote gelaufen. Die eingebaute Browser-Leiste der Claude-App lässt keine Service Worker zu, daher Chrome headless.

Fehlt etwas, oder kann fremder Inhalt aus preise.json/localStorage als HTML oder Skript wirken?
